# Migrating existing private repositories

This checklist is for two existing private repositories that currently share a chezmoi config, age identity, `~/.secrets` file, and `~/.gitconfig.local`. **Do not run either repository's broad `save.sh` or `apply.sh` while they overlap.** Keep each repository and its Git history; removing an encrypted source file does not erase earlier commits.

1. Review the live `~/.secrets` locally. Treat all existing entries as work-only until individually classified; never copy the old file into the personal repository. Confirm both encrypted sources decrypt with the **old** identity before replacing any keys. Do not display keys or secrets in logs, commands, or chat.
2. Choose an approved age-key backup and retrieval method for **each** repository; they need not use the same provider. Do not generate new age identities until each profile can securely back up and retrieve its own key.
3. Back up the existing source files and age identity securely outside the repositories. With `profile-id` files already in place, copy **only** this template's `init-age-key.sh` and `scripts/profile.sh` into each existing repo; do not replace install/save/apply yet. Generate a distinct identity for each profile with its `init-age-key.sh`. Back each up with its chosen method, and verify retrieval against its local identity before re-encrypting any files. Keep the old identity until **all** old files are migrated and checked.
4. Remove the personal repository's old encrypted `~/.secrets` source **without decrypting it into a personal destination**. Remove the work source for `~/.gitconfig.local`; retain the personal source for it and work identity in `~/.gitconfig.work`. Re-encrypt only the remaining, correctly owned `.age` sources to their respective profile recipients without printing plaintext. Do not use `chezmoi re-add` to rotate keys: it reads the live destination, which may belong to the other repository. Verify decryption of every new encrypted source with its own key, and ensure the opposite key cannot decrypt it.
5. Move the old live `~/.secrets` file into `~/.secrets/work/env.sh` with restrictive directory (`0700`) and file (`0600`) permissions. Create a separate personal `~/.secrets/personal/env.sh` containing **only** verified personal values (or an empty file). Rename the encrypted chezmoi sources to manage these destinations. Check the work Git settings in `~/.gitconfig.work` and the personal settings in `~/.gitconfig.local` without transferring work credentials.
6. Only after all sources and destinations are disjoint, update the common scripts from this template in **both** repositories and keep each repository's own `scripts/restore-age-key.sh` and key-backup instructions. Track `profile-id` (`personal` or `work`) and the work-only `template-paths` list. Audit `chezmoi managed` with each profile config for unexpected paths before applying either repo. Apply the new public shell loader last. A normal shell must load only personal env; `work-shell` must load work env in a child shell and stop exposing it on exit.

The former encrypted personal `~/.secrets` source may contain work credentials in existing Git history. Consult your retention and access requirements separately; changing today's source does not sanitize history. No step above requires pushing or committing without an explicit decision.
